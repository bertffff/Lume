# Редизайн Lume: состояние и план

Рабочий документ. Обновляется после каждого экрана. Владелец решений по виду — один (арт-директор), не параллельные исполнители.

## Правила, которые нельзя нарушать

- Ветка только `cursor/lume-greenfield-87d4`. Пуш без force. Коммиты атомарные по экранам (conventional).
- Экран = токены `--ds-*` + CSS-модуль на компонент. 0 инлайн-`style`, 0 `!important`, без «сырых» цветов и px в отступах (`apps/web/scripts/check-ds.mjs` в `pnpm lint`).
- Один акцент на экране; статусные цвета только как точка, иконка или строка текста.
- Основной текст ≥ 14 px. Контраст проверяет `ds/tokens/tokens.test.ts`.
- Не трогать API, контракты, БД, realtime. Не показывать вымышленные данные (длительность, качество, STUN/ICE).
- Готово = рубрика ≥ 4 по скриншотам на сидированных И пустых данных, минимум 2 итерации; затем гейты: `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm test:e2e`.
- Визуальные эталоны Playwright обновлять только после просмотра пар «было | стало» (тест останавливается на первом различии, остальные экраны прячутся за ним).
- Дешёвым бесплатным моделям (`opencode/*-free`) — только механика, разведка, поиск дефектов на скриншотах. Модель всегда указывать явно.
